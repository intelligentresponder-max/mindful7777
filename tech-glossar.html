Technik-Glossar

Alles, was beim Aufbau der Zahlungsabwicklung vorkommt — vom Payment Link bis zum Signing Secret. Tippe los, um zu filtern.

01Zahlungen

Payment Link
Eine fertige Bezahlseite hinter einer URL. Du verschickst den Link, die Zahlung läuft beim Anbieter — kein eigener Shop nötig.
Checkout Session
Ein einzelner Bezahlvorgang bei Stripe. Hat eine eigene ID und einen Status, an dem du erkennst, ob bezahlt wurde.
PSP
Payment Service Provider. Die Firma, die die Zahlung technisch abwickelt — Stripe, PayPal, SumUp.
Merchant of Record
Wer rechtlich als Verkäufer auftritt. Ist es die Plattform, kümmert sie sich um die Umsatzsteuer. Bist du es, musst du selbst melden.
3D Secure / SCA
Zusätzliche Kundenbestätigung per App oder TAN. Im europäischen Zahlungsverkehr vorgeschrieben.
Rückbuchung
Die Bank holt eine Zahlung auf Wunsch des Kunden zurück. Kostet zusätzlich eine Gebühr, auch wenn du im Recht bist.
SEPA-Lastschrift
Einzug direkt vom Konto. Meist ein fester Betrag pro Vorgang statt eines Prozentsatzes — bei großen Summen deutlich günstiger.
Auszahlung
Die Überweisung deines Guthabens vom Zahlungsanbieter auf dein Bankkonto, meist mit einigen Tagen Verzögerung.
Fulfillment
Alles, was nach der Zahlung passiert: Download freigeben, Zugang schalten, Mail verschicken.
OSS-Verfahren
EU-Meldeverfahren, über das du die Umsatzsteuer für Kunden in anderen Mitgliedstaaten zentral abführst.

02Webhooks

Webhook
Eine Nachricht, die ein fremdes System von sich aus an deine Adresse schickt, sobald etwas passiert. Du fragst nicht — du wirst benachrichtigt.
Endpoint
Die URL, an die diese Nachrichten gehen. Muss exakt stimmen: Weiterleitungen und Schrägstriche am Ende führen zu Fehlern.
Event
Das gemeldete Ereignis selbst, zum Beispiel eine abgeschlossene Zahlung. Hat einen Typ und eine eindeutige ID.
Payload
Der Inhalt der Nachricht — die eigentlichen Daten als JSON.
Roher Body
Der unveränderte Text der Nachricht. Für die Signaturprüfung zwingend nötig; wird er vorher in JSON umgewandelt, schlägt die Prüfung fehl.
Signing Secret
Der geheime Schlüssel, mit dem der Absender die Nachricht unterschreibt. Beginnt bei Stripe mit whsec_ und ist pro Endpoint verschieden.
Signaturprüfung
Der Abgleich von Nachricht und Unterschrift. Erst danach darfst du dem Inhalt glauben — sonst könnte jeder Zahlungen vortäuschen.
Idempotenz
Dieselbe Nachricht mehrfach zu verarbeiten darf nichts doppelt auslösen. Wichtig, weil Anbieter bei Störungen erneut zustellen.
Test- und Live-Modus
Zwei getrennte Welten mit eigenen Schlüsseln. Ein Schlüssel aus der falschen Welt lässt die Prüfung immer scheitern.
Statuscode 200 / 400
Die Antwort deines Servers. 200 heißt angenommen, 400 heißt abgelehnt. Der Absender wiederholt so lange, bis eine 2xx-Antwort kommt.

03Schlüssel & Sicherheit

API
Eine definierte Schnittstelle, über die zwei Programme miteinander sprechen.
Publishable Key
Der öffentliche Schlüssel, beginnt mit pk_. Darf im Browser stehen — er kann allein nichts anrichten.
Secret Key
Der geheime Schlüssel, beginnt mit sk_. Gehört ausschließlich auf den Server. Nie ins Repo, nie in einen Screenshot.
Umgebungsvariable
Ein Wert, der außerhalb des Codes hinterlegt wird. So bleiben Schlüssel aus dem Repository heraus.
HTTPS / TLS
Verschlüsselte Verbindung zwischen Browser und Server. Für Zahlungsseiten Pflicht.
PCI DSS
Sicherheitsstandard für Kartendaten. Wer die Eingabe dem Anbieter überlässt, reduziert seinen eigenen Aufwand erheblich.

04Code & Deployment

Repository
Der versionierte Projektordner. Enthält den Verlauf aller Änderungen.
Commit
Ein gespeicherter Änderungsstand mit Beschreibung. Die kleinste Einheit der Versionsgeschichte.
Push
Die lokalen Commits zum Server übertragen — bei dir zu GitHub.
Branch
Ein paralleler Entwicklungsstrang. Deiner heißt main.
.gitignore
Liste von Dateien und Ordnern, die bewusst nicht mitversioniert werden — allen voran node_modules.
package.json
Verzeichnis der Pakete, die dein Projekt braucht. Danach richtet sich, was beim Deploy installiert wird.
npm
Das Paketwerkzeug für Node.js. Installiert Bibliotheken in den Ordner node_modules.
Serverless Function
Eine einzelne Datei, die auf Anfrage startet, antwortet und wieder verschwindet. Kein Server, den du selbst betreiben musst.
Deployment
Die Veröffentlichung eines Stands. Neue Umgebungsvariablen greifen erst nach einem erneuten Deployment.
Statische Seite
Eine Seite aus fertigen Dateien ohne Programm dahinter. Schnell und günstig — kann aber keine Webhooks empfangen.
